# Engineering standards

Shared defaults for repositories maintained by [Forja Labs LLC](https://github.com/forjalabs-llc).

GitHub uses these contribution guidelines, support instructions, security policy, and issue / pull request templates when a repository does not define its own.

## Working agreement

1. Describe the problem and acceptance criteria in an issue.
2. Make a focused branch and a small, reviewable change.
3. Run the repository's documented checks.
4. Open a pull request with evidence, risks, and a rollback plan when needed.
5. Merge after checks pass; document behavior changes.

## Files

- [CONTRIBUTING.md](CONTRIBUTING.md): development and review process.
- [SECURITY.md](SECURITY.md): private vulnerability reporting.
- [SUPPORT.md](SUPPORT.md): questions and troubleshooting.
- [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md): respectful collaboration.
- [.github/ISSUE_TEMPLATE](.github/ISSUE_TEMPLATE): structured bug and feature requests.
- [.github/PULL_REQUEST_TEMPLATE.md](.github/PULL_REQUEST_TEMPLATE.md): review checklist.

These defaults do not add CI or branch protection to other repositories. Configure those per project. Choose an appropriate license for each new project before distributing it.
